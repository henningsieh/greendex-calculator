# Internationalization

## Official documentation

Confirm the installed `next-intl`, `i18n-iso-countries`, and `country-flag-icons` versions before changing locale or country presentation. `next-intl` does not provide a working `llms.txt` route, so use its [official documentation](https://next-intl.dev/docs). For country packages, use installed declarations and the official [`i18n-iso-countries` repository](https://github.com/michaelwittig/node-i18n-iso-countries) or [`country-flag-icons` repository](https://gitlab.com/catamphetamine/country-flag-icons). No third-party package skill is adopted. Compare all guidance with these Greendex rules.

The configured locale codes are `en-GB`, `de`, `es`, `fr`, `it`, `nl`, and `sl`. Each code is a full BCP-47 tag and reaches `Intl` unchanged, so it names both the message catalogue and the formatting rules: bare `en` is US English in CLDR, and `si` is Sinhala, not Slovenian. The switcher's flag comes from the language entry's `countryCode`.

## Date and time presentation

`packages/i18n/src/datetime/` owns every rendered date and time. It is the only module that may construct `Intl.DateTimeFormat` or call `Date.prototype.toLocale*`. `greendex/no-raw-date-formatting` enforces that, and `pnpm run lint` runs the guard's tests through `check:date-formatting`.

Pick a name from `dateFormats` instead of passing options:

- CLDR styles carry a locale's own conventions: `date.short`, `date.medium`, `date.long`, `date.full`, `time.short`.
- `dateTime.short` and `dateTime.medium` add the clock.
- Component formats exist only where no style fits: `date.numeric` for an editable or round-tripping field, `date.monthShort` and `date.monthLong` for a month label, `time.seconds` for a comparable stamp.

Use `useDateFormat()` in Client Components, `getDateFormat()` in Server Components and route handlers, and `createDateFormatter({ locale, timeZone })` where there is no request, such as email rendered from a background job. `format.range` renders a span as one localized range rather than two dates joined by a dash, and `format.pattern()` supplies an entry-field placeholder in the locale's field order.

Formatter output is canonicalised: every CLDR space separator becomes a plain space. Node and browsers ship different ICU/CLDR versions, and CLDR 49 replaced the thin spaces around a range's en dash, so an uncorrected range renders differently in the server process and in the browser and React reports a hydration mismatch. Normalising in the module is the only place that can cover every call site; do not re-add per-component string replacement, and keep the en dash. When a range must not wrap in a narrow column, use `whitespace-nowrap` rather than relying on an invisible character.

Every formatter requires an explicit IANA time zone, and both apps configure it on the provider. Never let a date resolve to the host zone: the server render and the browser would disagree, and a deployment would change the output. Format calendar dates and audit instants through the same module, and add a name to `dateFormats` rather than a local option object.

## Translation changes

- Calculator uses one JSON document per locale with nested namespaces. Cost Tracker uses domain JSON bundles in `apps/cost-tracker/src/messages/<locale>/`, composed by each locale's typed index. Keep namespaces inside the JSON; the merger rejects duplicate top-level namespaces.
- Add or rename a key in every locale file in the same change.
- Preserve identical object shapes across locale files.
- Use descriptive semantic keys rather than copying English display text into key names.
- Keep ICU placeholders and plural arguments consistent across locales.
- User-visible calculator text belongs in messages unless it is external data or user content.

## Cost Tracker one-source rule

Each Cost Tracker UI file reads one home bundle. Use the executable [file-to-bundle mapping](../../../apps/cost-tracker/src/messages/domains.ts) when adding a file; unmapped translator consumers fail the guard. Pass one distinct non-empty namespace string literal per file to `useTranslations` or `getTranslations`, and bind each component's translator as `t`. Repeated calls with the same namespace are allowed. The namespace root must match the home bundle, and each bundle contains only its own root and sub-namespaces. Share cross-domain copy through its owning component rather than reading a second bundle. `greendex/one-translator-source` enforces literal namespaces, one distinct source, and the `t` binding in the existing Cost Tracker UI lint scope; `src/messages/domains.test.ts` checks ownership and bundle roots.

## Cost Tracker API-error copy

The shared presentation module under `src/components/error-presentation/` owns the `apiErrors` bundle. Its explicit mapping precedes the general shared-component mapping. Bind its translator as `t` with the literal `"apiErrors"` namespace. Feature UI keeps its home bundle and passes error data to the owning component. Do not expose a foreign-bundle formatter through a hook or context.

Keep the canonical situation catalogue language-neutral. When adding or changing a reason, update `apiErrors.json` in every supported locale in the same change. English reason values must match `situationCatalog` exactly. Keep safe internal/network presentation overrides under `apiErrors.fallback`, separate from canonical reason copy. Composed prefixes must not be rendered alone.

Use structured detail identifiers from the canonical error contract when it defines them. Add their translations and producer/consumer tests together; do not invent a separate field-error catalogue. Keep all locale keys and ICU arguments aligned. Run the existing request-catalogue and ownership tests after changes. German copy must preserve domain distinctions; unreviewed locales may mirror English.

Pass request failures to `ErrorPresentation` and preview checklist gaps to `ErrorDetail`. Render validated server decisions that carry only a reason (for example the partner-setup recovery decision) with `ErrorReason`, never by re-mapping the reason to local copy. All three are exported from `src/components/error-presentation/error-presentation.tsx`. Keep the original error in feedback until rendering; toast descriptions accept the same component. Associate field corrections only with issues returned by `getORPCErrorPresentation`. Unidentified validation issues receive safe summary feedback rather than remote field prose.

For a new reason or detail, update its owning catalogue and validation in `error-contract.ts`, its producer, and every locale's `apiErrors.json` together. Add a producer test and an English/German rendered-presentation regression. Exercise missing-key and malformed-metadata fallback at that boundary. Run the shared presentation, `error-details`, request-catalogue, and domain-ownership unit suites. The request guard derives reason/detail coverage from the catalogues and completion-status coverage from the blocker schema.

## Server and client usage

- Server Components import `getTranslations`, `getLocale`, `getMessages`, or `setRequestLocale` from `@greendex/i18n/server`.
- Client Components import hooks and the provider from `@greendex/i18n/client`.
- Use `Link`, `redirect`, `useRouter`, and `usePathname` from `apps/calculator/src/lib/i18n/routing.ts` for localized navigation.
- Validate route locales with `isSupportedLocale` before rendering locale content.
- Do not introduce a second next-intl configuration inside a feature.

## Adding a locale

1. Add the language metadata in `packages/config/src/languages.ts`.
2. Add `packages/i18n/src/locales/<locale>.json` with the complete message shape.
3. Update country-name registration or locale presentation where required.
4. Verify static locale params, navigation, locale switching, and representative forms.
5. Update tests and documentation that enumerate supported locales.

## Country presentation

Country selection uses project utilities rather than translation messages alone. Keep ISO country codes as stored domain values and localize their presentation. Confirm country-library behavior from installed declarations and its official repository.
